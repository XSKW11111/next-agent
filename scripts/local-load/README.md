# Run local agent load in kind

Run `bash scripts/local-load/run-kind.sh` from this repository with Docker, kind, and `kubectl` available. The command requires the `kind-rolling-lab` context by default. Set `KIND_CLUSTER` to another kind cluster name if needed. The script builds the agent, SQLite, and Redis images and creates resources only in `next-agent-load`.

The Job sends 1,000 HTTP requests with 100 workers by default to an agent Service with two replicas. It assigns four intents in interleaved order, with 250 requests each for order status, product search, an Early Risers claim, and human handoff. Set `LOAD_TURNS` in `k8s/job.yaml` to a positive multiple of four to keep the split equal. Set `LOAD_CONCURRENCY` there to change the worker count. The JSON summary reports completed turns, errors, latency by intent, throughput, estimated tokens, and SQLite row counts. The Job reads every stored message pair after the timed run and checks it against the request ID's expected prompt and reply. It fails for any wrong pair, failed turn, or unequal intent count. Each run resets the disposable SQLite and Redis pods before starting the Job.

Each agent replica calls the repository's `runSupportTurn` LangGraph with a scripted model that makes one scenario-specific tool call. The SQLite HTTP service stores the session streak and the resulting customer and assistant message pair. Redis holds the immutable order fixture for ten minutes and is used only by order requests. Product search uses a fixed catalog and embedding. The claim uses a fixed eligible time and synthetic code. Handoff writes a pending proposal to a request-local store. These fixtures check graph routing and per-request output. They do not prove distributed durability or retry behavior for claims and handoffs. The test does not exercise the hosted Next.js API, Supabase, external model latency, or multi-turn session contention. SQLite has one writer, so higher concurrency can expose its write throughput limit. Reported request latency includes the graph, local service calls, and message persistence. SQLite readback runs after the timed interval.

SQLite uses an `emptyDir` volume. Deleting the SQLite pod or namespace loses its data. Redis persistence is disabled. These services are for disposable local tests. Remove everything with `kubectl delete namespace next-agent-load`. Docker images and the cluster's unrelated namespaces remain untouched.

The detailed design, boundaries, and one observed 1,000-request report are in `docs/local-k8s-load-design.md`. The script bundles the checked out dependencies with the local `esbuild` binary before building images, so install dependencies on the host first.
